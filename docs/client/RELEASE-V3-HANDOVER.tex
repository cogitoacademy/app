\section{4. Delivered capability}

\subsection{Economy, pricing, and incoming payment}

\begin{itemize}
	\item Four package defaults: 50 Marks at Rp350,000; 150 at Rp975,000; 250 at Rp1,500,000; 500 at Rp2,750,000.
	\item Exact top-up tiers use configured package Marks and unit prices plus the configured surcharge. Exact package amounts use package prices. Example checks: 31 Marks is Rp224,750; 176 is Rp1,188,000; 320 is Rp2,000,000; 600 is Rp3,450,000.
	\item Competition-scoped rate card. Online solo: Model UN and World Scholar's Cup 50 Marks and Rp200,000 fee; Debate and Olympiad 44 and Rp180,000; Essay, Business, Public Speaking 38 and Rp160,000.
	\item Group formulas: online total is solo plus 12 Marks per extra student; offline total is solo plus 22 Marks plus 20 per extra student. Tutor fee adds Rp30,000 online or Rp75,000 plus Rp50,000 per extra student offline. Rounding stays visible; no hidden redistribution.
	\item Quotes, bookings, and fee events keep immutable snapshots. A later admin edit never reprices an existing booking. Activation is explicit: saving a revision does not activate it.
	\item Incoming payment remains Midtrans. Only an authoritative success credits Marks once. Duplicate PAID, SETTLED, or reconciliation events do not re-credit. A payment after reservation expiry still credits the wallet once and never promises a seat.
\end{itemize}

\noindent\textbf{Primary code:} modules under \code{packages/api/src/modules/}: pricing, economy, payment, and wallet. \textbf{Admin surface:} \code{/admin-economy}. \textbf{Student surface:} \code{/balance}.

\subsection{Cohorts and masterclasses}

\begin{itemize}
	\item One class entity with kind cohort or masterclass. Cohorts have multiple sessions; a masterclass has exactly one.
	\item Draft, edit, publish, postpone, cancel, and minimum-enrollment check. Publishing an online session creates one Google Meet event per session through the meeting job. Failure stays retryable; retry does not create a duplicate event.
	\item In-person sessions use an existing admin-managed room. Room capacity must cover the target group size; assignment and relocation are guarded.
	\item Session tutors can differ. A same-time replacement keeps the time, fee ownership, and meeting identity, updates the attendee, and grants no new exit right.
	\item Tutors can report absence before or during a scheduled session. Notices under 24 hours are late and appear in tutor history.
	\item The tutor fee is flat per session and editable per class. All sessions of a class use the agreed class fee.
	\item Class and session content has one authored language. The API keeps canonical \code{titleEn}, \code{descriptionEn}, and \code{curriculumEn} names. No alternate-language column remains.
	\item Class covers are removed. Class cards and detail pages use text only.
\end{itemize}

\noindent\textbf{Primary code:} \code{modules/academy-class/}, \code{modules/meeting/}, \code{modules/room/}. \textbf{Surfaces:} \code{/classes}, \code{/classes/\$classId}, \code{/admin-classes}, \code{/my-classes}, \code{/class-reports}.

\subsection{Enrollment, installments, and capacity}

\begin{itemize}
	\item Full cohort plan holds 20 Marks per session; half holds 22 per session; single holds 25; masterclass holds 5.
	\item Odd session counts split the half plan as ceil then floor. Selected session IDs and both installment rates lock at enrollment.
	\item A 15-minute checkout lock holds seats and price. Concurrent last-seat attempts have at most one winner. The same student cannot hold overlapping entitlement to one session.
	\item A half plan reserves the unpaid half until its installment deadline. Non-payment releases future unpaid seats once. Reminders run seven days and one day before the half starts and recover after downtime.
	\item Late joiners split only their remaining sessions. Rejoining after removal is a new quote at the current half rate for future sessions.
	\item Withdrawal and cancellation return Marks only, never cash. A 20\% rounded charge applies to the relevant remaining allocation. Examples: 220 remaining returns 176; full 20 returns 16; half 22 returns 18; single 25 returns 20; masterclass 5 returns 4.
	\item Postponement grants a separate 72-hour penalty-free exit. An ordinary schedule change grants a contextual exit for the affected undelivered session until the earlier of notification plus 24 hours and the new start.
\end{itemize}

\subsection{Reports and branded PDF}

\begin{itemize}
	\item Exactly one report per delivered session across private, cohort, and masterclass sessions.
	\item Three required fields: discussion focus, strengths, and improvements. Total limit is 600 characters after documented normalization, enforced in the UI and server.
	\item Submitting a report completes the session, deducts the correct student allocations, and creates one tutor earned fee. A missing report keeps holds pending and creates no payable fee. Reminders repeat until resolved.
	\item Admin can complete or correct a report with the three fields, a delivery check, a required reason, actor and time history, and a tutor notification. An edit changes text and version only, never money or referral outcomes.
	\item Student export lists eligible reported sessions from the last three calendar months, newest first. Admin can export for any student. Layout uses the approved banner, logo, orange STUDENT REPORT label, session metadata, three feedback rows, footer generation date, and page numbers. Long content continues on labelled pages.
\end{itemize}

\noindent\textbf{Primary code:} \code{modules/report-export/}, report routes under the booking and class modules. \textbf{Surfaces:} \code{/class-reports}, booking detail, admin report workspace.

\subsection{Tutor tax and payout recording}

\begin{itemize}
	\item Tutor completion requires legal name and 16-digit NIK. NPWP stays optional. Existing published tutors may keep teaching, but a new payout requires the profile.
	\item Tax defaults: NIK and NPWP 2.50\%; NIK only 3.00\%; missing 3.00\%; admin override allowed. Rates support two decimals.
	\item Admin selects unpaid session fees as one batch. The preview shows gross, tax status or override, withholding, one Rp2,500 non-BCA transfer fee, and net. Actual transfer must equal net to mark fully paid.
	\item Prepare and recorded values keep tax, bank, and fee snapshots. Later profile or settings edits never recalculate a recorded payout. One earned session cannot enter two active allocations.
	\item A void keeps history and returns sessions to unpaid. If money moved, the transfer stays visible and requires reconciliation before repayment. Partial tutor payout is not supported.
	\item Monthly tax CSV sums non-void paid snapshots by actual payment date, not current tax profiles. Fields include legal name, NIK, NPWP, status, gross, applicable rates, withholding, net, monthly total, and payout detail for mixed rates. Output is formula-safe.
\end{itemize}

\noindent\textbf{Primary code:} \code{modules/tutor/}, payout routes; migration \code{0090} repairs bank snapshot columns. \textbf{Surfaces:} \code{/admin-tutor-payouts}, tutor earnings panel.

\subsection{Registration, friend referral, and KOL}

\begin{itemize}
	\item Email signup uses an empty OTP field plus Send code on one row, a 60-second cooldown, and atomic proof consumption only after account creation. Resend invalidates the old code. Email changes reset proof; referral correction does not.
	\item Google signup adds a referral step with Apply code or No referral code, no extra OTP. An interrupted choice resumes on next login. An existing matching account is reused without a new reward or attribution.
	\item One registration code is allowed, either friend or KOL. Welcome default is 15 Marks, friend reward default 15, semester cap default 75. Only student accounts participate.
	\item Friend reward is evaluated once at the referred student's first eligible completion. It credits the remaining cap, records a zero decision when capped, and never rolls over. A no-show penalty alone does not qualify.
	\item KOL campaign defaults are 30-day signup validity and 90-day attribution. Commission uses the snapshotted IDR purchase price, excludes gateway fees, rounds to whole rupiah, and counts repeated events once. Terms lock at signup.
	\item Settlement records actual external transfers with partial and overpaid readback, immutable reasoned adjustments, admin history, and a monthly current reconciliation CSV. A transfer never auto-allocates to another commission or offsets future liability.
	\item Full refund voids the effective obligation while keeping transfers and adjustments. Partial refund proration stays undefined and is never inferred.
\end{itemize}

\noindent\textbf{Primary code:} \code{modules/referral/}, \code{modules/auth/}, \code{modules/payment/}. \textbf{Surfaces:} \code{/referrals}, \code{/admin-referrals}, sign-up and Google callback.

\subsection{Competition catalog}

\begin{itemize}
	\item Two levels only: parent competition and child specialization. A child belongs to one parent. Cycles, self-parenting, and third levels are rejected.
	\item Admin can list, search, create, read, edit names, descriptions and order, archive or reactivate, and delete only unused entries. A referenced entry returns a conflict and must be archived.
	\item Stable identity: renaming or reordering never changes tutor assignments or historical booking, report, and fee identities. Codes become read-only after creation.
	\item Parent owns the versioned on-demand rate. Children inherit it and cannot override pricing. An unpriced draft cannot be sold.
	\item Archive hides the entry from new selections, discovery, and new publication. Existing assignments, accepted bookings, quotes, enrollments, reports, and financial snapshots remain readable and keep agreed terms.
	\item Four parent colours: light text, light background, dark text, dark background. Children inherit. Values must be opaque OKLCH numbers; CSS, variables, URLs, and alpha are rejected. Required labels stay visible without colour.
	\item One catalog feeds admin forms, tutor invitation and profile, discovery filters, booking selection and validation, rate editors, class forms, public tutor projections, calendar and report labels. No fixed seven-type runtime enum remains.
	\item The seed supplies seven parent competitions and 34 children. Migration \code{0078} removes superseded catalog rows; the catalog is not a closed list.
\end{itemize}

\noindent\textbf{Primary code:} \code{modules/competition-catalog/}, \code{modules/tutor-subjects/}. \textbf{Surfaces:} \code{/admin-competitions}, discovery filters, booking form, class editor.

\subsection{Content: Knowledge Bank, calendar, FAQ, Activities, blog}

\begin{itemize}
	\item Knowledge Bank and Competition Calendar moved from Sanity reads to database and API. Admin edits go live without an extra editorial workflow. Private Knowledge Bank PDFs use authenticated access through \code{KB\_PRIVATE\_BUCKET} or a local private directory.
	\item The calendar seed inserts 63 approved events with stable IDs and \code{onConflictDoNothing}. Reseeding never overwrites an admin edit. Calendar events need no object storage.
	\item FAQ stores rich text with safe paragraphs, lists, bold, italic, and links. English is required; Indonesian is optional with per-field fallback. Nine fixed categories; the full list is grouped by category. At most six active entries appear on the landing surface. The 55-entry bilingual seed is part of the default seed.
	\item Activities has one page with a Classes section and one Others article list. Classes read app class records. Others reads app \code{activity\_article} records: optional cover, required English and optional Indonesian title, summary and body, one WIB start time, location, and publication state. Upcoming or completed is derived server-side from the start time. Registration links live in the body.
	\item The bilingual blog is app-managed. Six tables cover media, categories, articles, versions, related articles, and galleries. Each locale publishes independently. A slug locks after first publish. The publish gate checks required fields, hero media and alt text, key facts, and gallery alt text. Public reads use \code{publicContent.blog.*} with rate limits; media use existing storage and R2 public URLs.
\end{itemize}

\noindent\textbf{Surfaces:} \code{/knowledge-bank}, \code{/calendar}, \code{/faq}, \code{/activities}, \code{/admin-knowledge-bank}, \code{/admin-blog}. \textbf{Migrations:} \code{0075}, \code{0077}, \code{0083}--\code{0084}, \code{0086}, \code{0089}.

\subsection{Business insights and admin operations}

\begin{itemize}
	\item Q15 splits four metric groups: IDR top-up receipts, delivered service in Marks and session counts, current future confirmed commitments with funded and unfunded states, and earned or unpaid tutor costs in IDR.
	\item Cash uses successful payment and refund event dates. Delivery uses session delivery date. Commitments are an as-of-now snapshot. Participant and session allocations are summed; original parent Marks fields are never mixed.
	\item No Marks-to-IDR booking conversion and no implied profit.
	\item Admin keeps operational queues for bookings, wallet lookup, rooms, tutor review, payouts, referrals, catalog, economy, achievements, Knowledge Bank, FAQ, Activities, and blog. Actions that change money or policy require a reason and preserve before and after values.
\end{itemize}

\subsection{Deployment order}

	\item Confirm the target database and take a verified backup. Rehearse restore before a production migration.
